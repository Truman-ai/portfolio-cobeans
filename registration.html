Participant Flow

참가자 화면: 단계형 접수

위아래 스크롤 없이 이전·다음 버튼으로 이동하고, 상단 진행 막대와 "STEP 1 / 7" 표시로 남은 단계를 알 수 있습니다.

  1. 인트로집회명·일시·장소·문의처. 주소를 누르면 지도 앱, 번호를 누르면 전화 연결
  2. 신청자 정보동반 인원 수만큼 이름 칸이 자동으로 생기고 총 인원이 바로 계산됨
  3. 참석 일정9개 세션 선택, "전체 참석" 버튼
  4. 식사 신청날짜·끼니별 인원, 일괄 적용·초기화. 총 인원을 넘지 않게 제한
  5. 숙박 신청밤별 인원, 같은 상한 제한
  6. 차량이용 여부와 탑승 위치 선택, 출발 일시 강조
  7. 기타 요청사항알레르기, 거동 불편, 숙소 요청 등
  8. 참가비용 안내참고 비용 안내, 계좌 복사 버튼
  9. 입력 확인입력한 내용 전체 요약 후 제출
  10. 완료공지용 카카오톡 채팅방 입장, 다른 사람 추가 접수

샘플 데이터로 재현한 화면입니다. 입력값(홍길동 외 2명)은 가상의 예시이고, 문의 번호와 계좌는 가렸습니다.

필수 입력 검증

빈 칸에 빨간 테두리와 안내 문구를 띄우고 다음 단계로 넘어가지 않습니다. 제출 직전에도 전체 단계를 다시 검사합니다.

Admin

담당자 화면: 접수 현황

암호를 입력하면 들어가는 7단계 관리자 화면입니다. 암호는 페이지 소스가 아니라 서버(Apps Script)에서 검증합니다.

  • 종합 대시보드접수 건수, 총 인원, 식사, 숙박, 차량
  • 참석 일정세션별 인원과 연인원
  • 식사 신청끼니별 인원과 합계
  • 숙박 신청밤별 인원과 합계
  • 차량 운행탑승자 명단과 인원
  • 기타 요청사항요청을 남긴 사람만 모아 보기
  • 접수 내역일정 필터, 이름 검색, CSV 내보내기

관리자 화면의 접수 내역 6건은 모두 가상의 샘플 데이터입니다.

Architecture

기술 구성

참가자 휴대폰제출 →Google Apps Script→Google 스프레드시트
담당자 PC암호 + 조회 →Google Apps Script검증 후 목록 →관리자 화면 집계
설정 파일 하나로 운영

집회명, 일정, 식사·숙박 날짜, 차량 선택지, 비용 안내, 검증 규칙을 한 파일에서 바꾸면 화면이 자동으로 바뀝니다. 다음 집회에도 다시 쓸 수 있습니다.

보안 판단

관리자 암호와 Apps Script 코드는 공개 저장소에 올리지 않고 서버 쪽에서만 검증합니다.

Process

제작 과정

첫날 약 10시간 동안 핵심 기능 대부분을 만들고, 이후 사용자 의견을 반영해 다듬었습니다.

  1. 9/10 오후첫 배포. 관리자 암호 노출을 막으려고 Apps Script 코드를 저장소에서 분리
  2. 9/10 오후글자 크기 버튼(5단계, 큰 글씨 기본), 식사·숙박 인원 상한 제한, iOS 확대 방지
  3. 9/10 저녁~밤참가비용 안내 화면 추가, 문구·금액·배치 다듬기
  4. 9/11 새벽필수 입력 검증 적용, 관리자 화면을 7단계 구성으로 개편
  5. 9/16접수 폼 화면 다듬기, 차량 안내 문구·선택지 수정
이후 이어진 작업

집회가 다가오면서 같은 주소는 다국어 집회 일정 안내 페이지로 발전했습니다. 시간대 자동 변환, 8개 언어, 집회별 고유 주소를 갖췄습니다.
